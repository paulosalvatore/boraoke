## Not captured — and why

- **In-app YouTube search results** — impossible without `YOUTUBE_API_KEY` (none configured, per the task's constraint). Captured the real degraded state instead (`patron-song-search-degraded-desktop.png`) plus the working paste-URL fallback, both honest.
- **"Karaoke days" chart with real multi-day data / "Top songs" populated** — the analytics store only had this one tour session's data (queued songs, none actually "played" via a real advance-to-completion), so the chart shows a single bar and "Top songs" honestly reports "No songs played in range." Not faked with a longer backfill.
- Mobile TV screen — explicitly out of scope per the brief (desktop/TV widths only).

## Visual defects observed (real, not staged)

1. **TV up-next rail truncates names to ~2 characters** (`tv-now-playing-1920x1080.png`, `-1440x900.png`): the "A seguir" cards show "Br…", "C…", "Di…" instead of "Bruno", "Carla", "Diego" — the truncation width looks too aggressive for the rail-card layout and reads as broken/cut off, not intentional ellipsis-of-a-long-name.
2. **Mobile "Enviar feedback" floating button overlaps queue content**: on narrow (390px) viewports the bottom-right feedback pill sits on top of the last visible queue row's song title/CANTAR button (`patron-room-populated-queue-mobile.png`, `patron-pending-approval-mobile.png`). It's a fixed-position overlay with no scroll-margin/safe-area reserved for it, so it obscures real content rather than floating clear of it.
